            Why write skew happens
            

              The example rule requires at least one replica online: east + west
              ≥ 1. Two transactions both read east = west = 1, then
              independently take a different replica offline.
            

            

              Snapshot isolation checks overlapping writes, so these disjoint
              writes both commit. Serializable validation also checks recorded
              reads; the second transaction aborts because the first changed a
              value it relied on.
            

          

          

            What this implementation guarantees
            

              This custom model uses a fixed key set and point reads. Snapshot
              mode rejects writes to keys changed after the transaction began.
              Serializable mode additionally rejects any recorded read whose
              latest version changed, even if its value later changed back.
            

            

              Serializable mode is conservative optimistic validation in commit
              order, not PostgreSQL SSI. It may reject histories another
              serializable algorithm could allow, including stale read-only
              transactions. No range reads, inserts, deletes, or phantom
              predicates are modeled.
            

            

              SQLite durably stores the modeled state and immutable command
              journal. Each command atomically updates both. Logical
              transactions span many HTTP requests; they do not keep a SQLite
              transaction open between requests. This is a bounded teaching
              engine, not a production database.
            

          

          

            Retries, persistence, and limits
            

              Reusing a transaction ID with the same client returns its existing
              state. Repeating commit or abort preserves a terminal outcome and
              creates no duplicate record versions. Every accepted command
              attempt still appends a journal event. Rejected malformed or
              invalid-state requests do not.
            

            

              20 workspaces per database; 100 transactions and 500 events per
              workspace; at most 12 active transactions. State survives restart.
              Client labels are not authentication; keep the loopback server
              local and use fictional records. Hashes detect inconsistency, not
              malicious database-owner rewrites.
